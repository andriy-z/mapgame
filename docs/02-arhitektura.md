# Технологічний стек та архітектура

Похідне від `00-opys-gry.md`. Тут — як гра влаштована технічно.

## Тверді обмеження

1. **Відкрив `index.html` подвійним кліком — і працює.** Без локального
   сервера, без `file://`-обмежень (жодного `fetch`, жодних ES-модулів
   `import`/`export`).
2. **Без білд-кроку.** Не треба нічого компілювати чи "пересобирати"
   перед грою. (Якщо колись знадобиться `import`-синтаксис чи npm —
   додамо `esbuild`, що збирає в один HTML. Поки не потрібно.)
3. **Не розробники.** Код простий і читабельний, без хитрих патернів.
4. **Модульно.** Додати персонажа / перешкоду / бонус / завдання / карту
   = один маленький новий файл + один рядок у маніфесті. Головний код
   не чіпаємо.

## Мова і рендер

- Чистий JS (ES2015+), без TypeScript.
- **Рендер — DOM.** Кожен тайл і фішка — окремий елемент (видно в
  DevTools, обробники подій на елементах, без ручного hit-test по
  координатах Canvas).
- **Картинки — PNG** (прозорий фон), генеруємо AI. Персонажі, бонуси,
  помічники — точно PNG (SVG виходить негарний). Тайли карти — PNG або
  плоский колір, вирішимо на етапі 0.
- Спрайт у коді = `<img>`, спозиційований по клітинці. Картинку беремо
  **лише за id** зі скіна (`Game.images[id]` → `skin/<id>.png`). Відносний
  шлях у `file://` працює.
- **Скін** [ЗАФІКСОВАНО] — усі картинки гри (плитки, фішки, точки шляху,
  мітки) в одній теці `skin/` плюс `skin/skin.js`, що реєструє їхні id
  (`Game.registerImage(id, file)`), а також звуки — музика й фанфара
  (`Game.registerSound(id, file)`). Новий стиль = інша тека з тими самими
  іменами файлів, код не змінюється.
- **Камера**: контейнер `viewport` з `overflow:hidden`, всередині
  контейнер `world` з `transform: translate(...)`; зсув рахується від
  середньої точки двох героїв. Герой не може відійти так, щоб напарник
  вийшов за межі `viewport`.

## Завантаження скриптів

`index.html` підключає файли звичайними `<script>`-тегами у визначеному
порядку: спершу `core/registry.js`, потім усі модулі-сутності, потім
`core/engine.js` і решта ядра, останнім — старт гри.

Список файлів тримаємо в одному місці як маніфест (масив шляхів), щоб
додавання модуля було одним рядком.

## Реєстр (`Game`)

Один глобальний об'єкт. Кожен файл-сутність реєструє себе:

```js
// src/characters/moomintroll.js
Game.registerCharacter({
  id: 'moomintroll',
  name: 'Мумі-троль',
  move: 5,                     // базових кроків за хід
  image: 'moomintroll',        // id картинки зі скіна
});
```

```js
// src/obstacles/wall-door.js
Game.registerObstacle({
  id: 'wall-door',
  name: 'Двері в мурі',
  blocks: true,                // перекриває шлях, поки не пройдено
  task: 'math',                // який тип завдання відкриває
  image: 'wall-door',          // id картинки зі скіна
});
```

Так само `registerBonus`, `registerTask`, `registerMap`.

## Структура тек

```
index.html            точка входу (маніфест + порядок скриптів)
src/
  core/
    registry.js        об'єкт Game + функції register*
    rules.js           правила руху: пошук шляху, «напарник на екрані», перемога
    engine.js          стан гри, черга ходів, хода по шляху
    view.js            малювання карти, фішок, шляху; камера; верхня панель
    input.js           миша / клавіатура / кнопки → команди рушія
    sound.js           фонова музика, фанфара фінішу, кнопка 🔊/🔇
    task.js            вікно завдання: відкрити, закрити, розв'язано чи ні
    quest.js           космос за телепортом: окремий рівень, хода героя, повернення
    token.js           фішка: коло з аватаркою + артефакти (docs/07-fishka.md)
  mapgen/              генератор карт (гра — «Нова гра», і tools/)
  characters/          один файл на персонажа
  obstacles/           один файл на перешкоду
  artifacts/           один файл на артефакт фішки (wings.js — крильця, boots.js — чоботи,
                       duck.js — качечка, stilts.js — ходулі, sled.js — санчата,
                       pepper.js — перчинка, telescope.js — підзорна труба,
                       hoverboard.js — літаюча дошка, antennae.js — антенки)
  bonuses/             один файл на приз (wings, boots, duck, stilts, sled, pepper,
                       look.js — зміна лука; balloon.js — кулька і harmonica.js —
                       гармошка: разові, з методом act(game, done))
  tasks/               один файл на тип завдання (read-word.js — обрати слово,
                       build-word.js — скласти слово з літер, find-picture.js —
                       обрати картинку, spot-word.js — знайти слово без помилки,
                       count.js — приклад до 10)
  quests/              один файл на космічний квест за телепортом
                       (dark-room.js — темна кімната-лабіринт з ліхтариком)
  content/             вміст: words.js — слова з картинками,
                       avatars.js — аватарки фішок
  maps/                один файл на карту-рівень (з генератора)
skin/                  скін: усі PNG і WAV + skin.js (id → файл)
tools/                 сторінка генератора карт з прев'ю (розробка)
docs/                  цей та інші описи
design/                чернетки стилю (відкривати в браузері)
```

## Стан гри

Один об'єкт `Game.state`: позиції героїв, чия черга (дитина/дорослий),
скільки кроків лишилось цього ходу, зібрані бонуси, статуси перешкод.
Без бібліотек стану.

Збереження/відновлення гри (localStorage) — не в POC-етапі 0, додамо
пізніше за потреби.

## Карта як дані

Файл карти описує сітку (2D-масив типів клітинок), стартові позиції
героїв, позицію фінішу, розстановку перешкод / скринь / помічників.
Рендер і рушій читають ці дані — самі карти коду не містять.
