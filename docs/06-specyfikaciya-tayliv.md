# Специфікація плиток (тайлів)

Похідне від `05-generator-karty.md` (розділи «Типи терену» й «Автотайлінг»).
Цей файл — **самодостатнє технічне завдання на арт**: які файли потрібні, як
вони називаються і яким правилам мусять підкорятися, щоб карта склалась.

Позначки: **[ЗАФІКСОВАНО]** — рішення прийняте; **[ПРОПОЗИЦІЯ]** — ще ні.

## Навіщо

Арт мусить мінятись без коду. Хочу інший стиль — беру цю спеку, віддаю
зовнішньому інструменту (AI, художник, свій скрипт), отримую **той самий
набір файлів з тими самими іменами**, кладу в `assets/tiles/` — і все
працює. Ні генератор, ні резолвер, ні рендер, ні реєстр не міняються.

Контракт між артом і кодом рівно один: **id плитки → шлях до файлу**
(`src/tiles/terrain.js`). Ім'я файлу = id + `.png`.

## Що саме потрібно [ЗАФІКСОВАНО]

**144 файли** у `assets/tiles/` — трава плюс один набір автотайлінгу:

| Файли | Скільки | Що це |
|---|---|---|
| `grass-0.png` … `grass-2.png` | 3 | трава, три взаємозамінні варіанти |
| `forest-<маска>.png` | 47 | ліс |
| `mountain-<маска>.png` | 47 | гори |
| `water-<маска>.png` | 47 | вода |

Імена — рівно такі: маленькі літери, дефіс, десяткове число без нулів
попереду. Жодних `forest-01.png`, `Forest-1.png`, `forest_1.png`.

Маски — **не суцільний ряд 0..46**, а самі значення 8-бітної
маски; їх рівно 47:

```
0 1 4 5 7 16 17 20 21 23 28 29 31 64 65 68 69 71 80 81 84 85 87 92 93 95
112 113 116 117 119 124 125 127 193 197 199 209 213 215 221 223 241 245
247 253 255
```

## Технічні вимоги до файлу [ЗАФІКСОВАНО]

- **PNG**, 64 × 64 пікселі. Усі 144 файли однакового розміру.
- **Повністю непрозора.** Плитка покриває клітинку цілком; рендер малює
  рівно одну картинку на клітинку і нічого під нею немає.
- Отже, **фон плитки терену — трава**: там, де в цій масці терену немає,
  має бути намальована трава, візуально того самого вигляду, що
  `grass-0.png`.
- Наслідок, з яким треба жити: **змінив вигляд трави — перегенеруй усе**.
  (Альтернатива — прозорі краї й трава окремим шаром — вимагала б двох
  картинок на клітинку, тобто зміни рендера. Відхилено: рендер лишається
  однією стрічкою `tiles[y][x]` → `<img>`.)
- Без полів, без рамок, без тіні за межами полотна.
- Колір sRGB. Палітру не фіксуємо — це і є те, що міняється.
- Розмір 64 можна змінити (наприклад на 96 чи 128) — але **одразу для всіх
  файлів**; рендер масштабує плитку під клітинку сам.

## Модель автотайлінгу [ЗАФІКСОВАНО]

Номер у назві — 8-бітна маска сусідів **того самого терену**, за
годинниковою стрілкою від півночі:

| Біт | Сусід | | Біт | Сусід |
|---|---|---|---|---|
| 1 | Пн — зверху | | 16 | Пд — знизу |
| 2 | ПнСх | | 32 | ПдЗх |
| 4 | Сх — справа | | 64 | Зх — зліва |
| 8 | ПдСх | | 128 | ПнЗх |

**Біт стоїть** → з того боку масив продовжується, краю не малюємо.
**Біта немає** → там межа: малюємо край, а решту поля заповнює трава.

**Діагональ рахується, тільки якщо стоять обидві сусідні сторони.** Інакше
форму кута однаково визначають сторони, і діагональ нічого не додала б.
Тому з 256 комбінацій лишається 47 різних форм.

За межами карти вважається, що терен той самий — тому масив на краю екрана
йде «за кадр».

Кілька прикладів (`X` — `forest`, `mountain` або `water`):

| id | Що це на вигляд |
|---|---|
| `X-0` | окремий острівець, кругленький з усіх боків |
| `X-17` | середина вертикальної смуги (Пн + Пд) |
| `X-68` | середина горизонтальної смуги (Сх + Зх) |
| `X-5` | кут: смуга йде вгору і вправо (Пн + Сх), ПнСх — трава: увігнутий кут вигризено |
| `X-7` | те саме, але ПнСх теж терен — кут заповнений |
| `X-255` | суцільна середина масиву, трави немає взагалі |

## Правила стиковки — головне [ЗАФІКСОВАНО]

Плитки ставляться поруч наосліп, тому геометрія межі не може бути
«художньою». Вона задана числами, і ці числа однакові для всіх трьох
теренів і всіх масок.

Нехай `S` = 64 (розмір), `INSET` = 12, `R` = 12.

1. **Область терену — прямокутник** із заокругленими кутами:
   - ліва межа: `0`, якщо стоїть біт заходу (64), інакше `INSET`;
   - права: `S`, якщо стоїть біт сходу (4), інакше `S - INSET`;
   - верхня: `0`, якщо північ (1), інакше `INSET`;
   - нижня: `S`, якщо південь (16), інакше `S - INSET`.
2. **Зовнішній (опуклий) кут заокруглюється** чвертю кола радіусом `R`
   тільки там, де **обидва** сусідні біти сторін не стоять (напр. ПнЗх —
   коли немає ні півночі, ні заходу).
3. **Внутрішній (увігнутий) кут**: якщо обидві сторони кута стоять, а
   діагоналі немає — з того кута плитки вигризаємо чверть кола (див.
   «Радіус увігнутого кута»). Решта кутів — гострі 90°.
4. **Там, де біт стоїть, терен доходить до самого краю плитки** і на цьому
   краю виглядає однаково в усіх масках, де цей біт стоїть. Це те, що
   робить шов невидимим: дві сусідні плитки завжди мають узгоджені біти
   (якщо праворуч від A той самий терен, то ліворуч від B — теж).
5. **Нічого не виступає за полотно.** Крони, вершини, брижі, тіні —
   усе всередині 64 × 64.
6. **Декор не перетинає межу терену.** Дерево не звисає на траву; якщо
   крона не влазить у маску — її просто немає в цій плитці.
7. **Смуга по межі назовні** (тінь від масиву, пісок біля води) — рівно
   `4 px` уздовж контуру, і **тільки там, де є межа**; біля краю плитки, де
   масив продовжується, смуги немає, інакше вона проступить посеред масиву.
8. **Облямівка всередині** (темніший край лісу/скелі, піна води) — `3 px`
   уздовж того самого контуру, за тим самим правилом.
9. Трава у полі плитки має бути **того самого середнього тону**, що
   `grass-0`, інакше поле піде плямами.
10. **Жодної випадковості на льоту**: один файл — одна картинка. Варіативність
   уже забезпечена трьома травами і маскою.

Ці числа (`INSET`, `R`, ширини смуг) можна змінювати — але **однаково для
всіх файлів**. Змінив `INSET` тільки в лісі — ліс і гори перестануть
стикуватись між собою по спільному краю трави.

### Радіус увігнутого кута — не вільний параметр

Він має дорівнювати **рівно `INSET`**, а центр дуги стояти в точці, зміщеній
від кута плитки на `INSET` по обох осях.

Чому: сусідні плитки в такій конфігурації підходять до цього ж кута своїми
прямими межами, які стоять якраз на відстані `INSET` від краю. Дуга радіусом
`INSET` торкається цих прямих по дотичній — межа масиву проходить кут без
зламу і без сходинки. Будь-який інший радіус дасть видимий стик.

Зовнішній радіус `R` при цьому лишається вільним: обидві його дотичні
належать тій самій плитці.

## Трава окремо [ЗАФІКСОВАНО]

Три файли `grass-0..2` — це **не** різні типи трави, а той самий газон із
різним дрібним декором. Генератор обирає варіант хешем від координат
(`world.hash(x, y) % 3`) — суто щоб поле не рябіло сіткою.

- Однаковий базовий колір і яскравість у всіх трьох.
- Декор дрібний і рідкий: кущик, кілька квіточок, камінець. Ніяких великих
  плям — вони самі стануть «сіткою», якої ми уникаємо.
- Без напрямку: варіанти лягають поруч у будь-якому порядку й повороті.
- `grass-0` — найспокійніший, бо саме він визначає, як має виглядати
  трав'яне поле в плитках терену.

## Чому 47, а не 16 [ЗАФІКСОВАНО]

Простіший набір на 16 (маска лише зі сторін) пробували й прибрали. Без
діагоналей внутрішні кути масиву гострі, а два масиви, що торкаються по
діагоналі, не з'єднуються — і артом це не лікується, бо потрібної картинки
в наборі немає. Перевірка на випадкових масивах (60 розкладок 8 × 8,
вибірка що чверть пікселя вздовж кожного шва), найдовший розрив на шві:
на 47 — **0.25 px** (точка дотику дуги, її з'їдає згладжування), на 16 —
**11.75 px**.

## Промт А — згенерувати скрипт (рекомендований)

(Саме так зроблено поточний програмний арт; його скрипт живе поза грою —
`~/Projects/maxmap-tilegen/gen-tiles.py`.)

Малювати 144 картинки окремо не можна: жодна модель не витримає піксельної
точності межі. Тому просимо не картинки, а **програму**, яка їх намалює:
геометрія тоді береться з формул і збігається за побудовою, а стиль —
з тексту промта.

```text
Напиши скрипт на Python 3 (тільки стандартна бібліотека, PNG пиши сам через
zlib + struct, без Pillow), який генерує 144 PNG-плитки 64×64 у теку
assets/tiles/. Скрипт має бути детермінованим: два запуски дають байт-у-байт
однакові файли.

ФАЙЛИ
  grass-0.png, grass-1.png, grass-2.png
  forest-<маска>.png,  mountain-<маска>.png,  water-<маска>.png
  де <маска> — 47 значень:
  0 1 4 5 7 16 17 20 21 23 28 29 31 64 65 68 69 71 80 81 84 85 87 92 93 95
  112 113 116 117 119 124 125 127 193 197 199 209 213 215 221 223 241 245
  247 253 255

ЩО ОЗНАЧАЄ НОМЕР
Номер — маска сусідів того самого терену: 8 біт за годинниковою стрілкою
від півночі — 1 = Пн, 2 = ПнСх,
4 = Сх, 8 = ПдСх, 16 = Пд, 32 = ПдЗх, 64 = Зх, 128 = ПнЗх. Діагональний біт
має право стояти, тільки якщо стоять обидві його сусідні сторони — саме
тому різних масок 47, а не 256 (список вище отримується перебором 0..255 і
скиданням «неправомірних» діагоналей).
Біт стоїть — з того боку масив продовжується; біта немає — там межа масиву.

ГЕОМЕТРІЯ (обов'язково саме така, це умова стиковки)
Розмір S = 64, відступ INSET = 12, радіус кута R = 12.
Область терену — прямокутник:
  left   = 0        якщо стоїть біт 64 (захід),  інакше INSET
  right  = S        якщо стоїть біт 4 (схід),    інакше S - INSET
  top    = 0        якщо стоїть біт 1 (північ),  інакше INSET
  bottom = S        якщо стоїть біт 16 (південь),інакше S - INSET
Зовнішній (опуклий) кут заокруглюється чвертю кола радіусом R лише там, де
обидва сусідні біти сторін не стоять (напр. верхній лівий — коли немає ні
півночі, ні заходу).
Внутрішній (увігнутий) кут: якщо обидві сторони кута
стоять, а діагонального біта немає, з цього кута плитки вигризається чверть
кола радіусом рівно INSET із центром за INSET від кута по обох осях. Саме
INSET, не R: тоді дуга торкається меж сусідніх плиток по дотичній і масив
проходить кут без сходинки.
Решта кутів — гострі 90°.
Усе, що поза цією областю, — трава, візуально ідентична grass-0.
Уздовж межі (тільки там, де межа є, не вздовж краю плитки з виставленим
бітом): смуга 4 px назовні — тінь від масиву / пісок біля води; облямівка
3 px усередині — темніший край / піна.
Декор (дерева, вершини, брижі, квіти) не виходить за область терену і не
виходить за полотно 64×64. Не влазить — не малюємо.
Малюй із суперсемплінгом 3×3 на піксель, щоб краї були гладкі.

СТИЛЬ
<ОПИШИ ТУТ СТИЛЬ, ЯКИЙ ХОЧЕШ: палітра, настрій, вигляд лісу/гір/води,
рівень деталізації. Наприклад: «м'який мультяшний вигляд, приглушені
кольори книжок про Мумі-тролів, ліс — округлі крони двох відтінків,
гори — сіро-блакитні вершини зі снігом, вода — спокійна, з рідкими
хвильками, трава — тепла зелена з дрібними квіточками».>
Межі м'які, низькоконтрастні, без чорного контуру. Силует органічний, а не
геометричний. Плитка непрозора, покриває клітинку цілком.

ТРАВА
grass-0 — чиста трава, вона ж фон усіх плиток терену.
grass-1 і grass-2 — та сама трава з дрібним декором (кущики, квіточки).
Однаковий базовий тон у всіх трьох; декор дрібний і рідкий, без напрямку:
плитки лягають поруч у будь-якому порядку.

ПЕРЕВІРКА
У кінці скрипт друкує, скільки файлів записав. Має бути рівно 144.
```

## Промт Б — намалювати текстури, геометрію зібрати скриптом

Якщо хочеться справжнього мальованого арту, а не програмного. Модель малює
**чотири безшовні текстури**, а межі й маски вирізає маленький скрипт — тоді
стиковка знову гарантована геометрією, а не старанністю моделі.

```text
Намалюй 4 безшовні (tileable) текстури 512×512 PNG, в одному стилі й одній
палітрі, без рамок, без тіней по краю, без окремих великих об'єктів у центрі:
  grass.png    — трава, рівномірна, спокійна
  forest.png   — крони лісу зверху, суцільний масив
  mountain.png — скелі й вершини зверху, суцільний масив
  water.png    — вода, спокійна, з дрібними хвильками
Стиль: <ОПИШИ СТИЛЬ>.
Кожна текстура має стикуватись сама з собою по всіх чотирьох краях.
```

А далі — другий промт, у якому з цих текстур збирається набір:

```text
Напиши скрипт на Python 3 (стандартна бібліотека + PNG через zlib/struct),
який з чотирьох безшовних текстур 512×512 (grass.png, forest.png,
mountain.png, water.png) нарізає 144 плитки 64×64 у assets/tiles/ за такими
іменами й такою геометрією:
<СЮДИ ВСТАВ БЛОКИ «ФАЙЛИ», «ЩО ОЗНАЧАЄ НОМЕР» І «ГЕОМЕТРІЯ» З ПРОМТА А>
Кожна плитка = трава з grass.png, поверх якої за маскою області вирізано
шматок відповідної текстури терену. Щоб масив не повторювався сіткою, бери
шматок текстури за координатами, що залежать від id плитки. По межі області
додай смугу 4 px назовні (затемнення 13 % / пісок для води) і облямівку
3 px усередині (затемнення 18 % / освітлення для води). Краї згладь.
grass-0..2 — три різні шматки grass.png.
```

## Чек-лист приймання

Перш ніж класти новий арт у `assets/tiles/`:

1. Рівно 144 файли, імена точно за списком.
2. Усі 64 × 64 (або всі однакового іншого розміру), PNG, непрозорі.
3. Відкрити `tools/map-generator.html`, згенерувати 3-4 різні seed-и.
4. Дивитись **на шви**: уздовж прямої межі масиву не має бути ні сходинки,
   ні світлішої/темнішої смуги, ні розриву.
5. Дивитись **на траву**: поле не має розпадатись на квадрати.
6. `X-255` посеред масиву не має показувати ані краю, ані облямівки.
7. Внутрішні кути мають бути заокруглені, а масиви — з'єднуватись по
   діагоналі.
